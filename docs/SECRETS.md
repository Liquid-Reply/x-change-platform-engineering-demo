# Secret Management

## Overview

```
secrets/<env>.env  ──►  bootstrap.sh  ──►  K8s Secrets
     │                       │
     │                       ├──► github-token (argocd)
     │                       ├──► backstage-secrets (backstage)
     │                       └──► dt-details (opentelemetry)
     │
     └──► scripts/dynatrace.py (if DT enabled)
              ├──► monaco-secret (dynatrace)
              └──► argocd-notifications-secret (argocd)
```

## Setup

1. Copy the template:
   ```bash
   cp secrets/template.env secrets/minikube.env
   ```

2. Fill in your values (only `GITHUB_TOKEN` is required)

3. Run bootstrap:
   ```bash
   ./bootstrap.sh minikube
   ```

## Secret File Format

```bash
# secrets/<env>.env

# Required
GITHUB_TOKEN=ghp_xxxxxxxxxxxx

# Optional: Dynatrace
DT_ENV_NAME=abc12345
DT_ENV=live
DT_RW_API_TOKEN=dt0c01.xxx
DT_OAUTH_CLIENT_ID=dt0s02.xxx
DT_OAUTH_CLIENT_SECRET=xxx
DT_OAUTH_ACCOUNT_URN=urn:dtaccount:xxx
```

## K8s Secrets Reference

| Secret | Namespace | Source | Required |
|--------|-----------|--------|----------|
| `github-token` | argocd | GITHUB_TOKEN | Yes |
| `backstage-secrets` | backstage | Multiple (derived) | Yes |
| `dt-details` | opentelemetry | DT_* vars or placeholder | No |
| `monaco-secret` | dynatrace | Generated from DT_RW_API_TOKEN | No |
| `argocd-notifications-secret` | argocd | DT_* vars | No |

## Backstage Secrets Keys

Generated by `bootstrap.sh` from config and secrets:

| Key | Source |
|-----|--------|
| `BASE_DOMAIN` | config/<env>.env |
| `ARGOCD_PORT_NUMBER` | config/<env>.env |
| `BACKSTAGE_PORT_NUMBER` | config/<env>.env |
| `ARGOCD_TOKEN` | Generated at runtime |
| `GITHUB_TOKEN` | secrets/<env>.env |
| `GITHUB_ORG` | Derived from REPO_URL |
| `GITHUB_REPO` | Derived from REPO_URL |
| `DT_TENANT_NAME` | DT_ENV_NAME or "placeholder" |
| `DT_TENANT_LIVE` | Derived from DT_ENV_NAME |
| `DT_TENANT_APPS` | Derived from DT_ENV_NAME |
| `DT_SSO_TOKEN_URL` | Static if DT enabled |
| `DT_OAUTH_*` | secrets/<env>.env |
| `DT_ALL_INGEST_TOKEN` | Generated or "placeholder" |

## Environment-Specific Behavior

### Minikube (No Dynatrace)
- Uses `dt-details-placeholder.yaml` for OpenTelemetry
- Backstage DT_ keys set to "placeholder"
- Platform fully functional without observability

### Codespaces (With Dynatrace)
- Secrets from Codespace secrets (environment variables)
- Full Dynatrace integration enabled
- Monaco configures DT tenant automatically
